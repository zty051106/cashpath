# CashPath 项目大纲

## 1. 产品定位

**个人消费与还款决策沙盘。**围绕“怎样支付一笔大额支出，才能兼顾成本和现金余量”提供可解释的方案比较。

首批目标用户假设：刚工作、有固定必要支出和备用金要求的年轻人。先用用户访谈与样例试用验证这一假设，再扩展到收入不固定的人群。

产品价值用以下问题验证：

- 用户是否能在几分钟内输入足够的条件？
- 用户是否看懂某方案在哪一天造成缺口？
- 用户是否能用结果调整支付方式、购买时间或预算？
- 用户是否能追溯每个结论的金额、日期和假设？

## 2. 完整用户流程

1. 填写可用余额、收入安排、必要支出及已有还款。
2. 填写商品现金价、分期首付款、每期付款和所有已知费用。
3. 设置备用金底线、允许推迟购买的天数和比较期限。
4. 运行正常情景及选定的压力情景。
5. 查看成本、余额曲线、缺口和候选方案。
6. 修改购买日期、预算或分期条件，重新比较。

第一版以手动输入和样例导入为主，减少用户准备资料的负担。

## 3. 金融方法与计算口径

### 3.1 成本与资金时间价值

- 名义成本：分别展示商品付款、手续费和总支付金额。
- 现值：使用用户明确给定的年有效折现率，按实际天数折现，展示折现假设；零折现率也是有效输入。
- IRR / XIRR：以实际融资金额与后续还款现金流计算隐含资金成本，说明现金流符号、首期日期及费用是否已包含。
- 等间隔月度 IRR 换算有效年利率时使用 `(1 + 月利率)^12 - 1`。
- XIRR 按 ACT/365 日期口径实现；不得与月度 IRR 混用而不说明。
- 非融资场景不强行计算年化利率；无解、多解或超出支持范围时明确返回状态。

数值核验样例：融资 6,000 元、首期一个月后、等间隔偿还 12 期，每期 530 元，无其他费用。总支付 6,360 元；月度 IRR 约 0.908032%，有效年利率约 11.45738%。该样例不表示任何真实金融产品报价。

### 3.2 现金流与流动性约束

- 第一版支持人民币单币种，账务金额用整数分表示，并检查范围与溢出。
- 按日期展开收入、必要支出、已有还款和新增支付。
- 明确同日现金流的执行顺序，并标记“资金需先到账”的假设。
- 区分费用与自有账户间转账，避免重复计算支出。
- 输出最低余额及其日期、首次低于备用金底线的日期、缺口金额和关联事件。
- 购买推迟后，首付款、分期开始日等事件必须一起更新。
- 默认展示 90 天余额；评估某方案是否满足约束时，至少覆盖该方案全部付款，避免遗漏后续负担。

### 3.3 压力测试

首版支持明确参数的情景变换：

| 情景 | 参数示例 | 观察结果 |
| --- | --- | --- |
| 正常 | 原始输入 | 基线最低余额及成本 |
| 收入延迟 | 某笔工资延迟 14 天 | 缺口是否提前、扩大 |
| 收入下降 | 指定期间收入减少 20% | 还款和必要支出的承受能力 |
| 突发支出 | 某日新增 2,000 元支出 | 备用金底线是否被突破 |

情景是条件假设，不代表事件的预测概率。允许组合情景，报告保留全部参数。

### 3.4 方案搜索与取舍

- 在用户允许的购买日期和有限支付方案中枚举候选。
- 检查每个候选在指定情景下能否满足备用金与等待期限约束。
- 比较成本、最低现金余量和等待时间。
- 筛除在所有比较维度都不更好且至少一项更差的方案，即被其他方案支配的方案。
- 返回有明确取舍的候选集合，避免用任意加权分数声称存在唯一最佳方案。
- 不可行时说明具体失败约束；给出放宽预算、日期等参数后的比较入口。

## 4. 工程结构

| 模块 | 责任 |
| --- | --- |
| `money` / `date` | 金额、日期、周期规则和输入校验 |
| `valuation` | 现值、IRR / XIRR、求解状态 |
| `cashflow` | 事件展开、余额路径、约束检查 |
| `scenario` | 压力情景变换与结果比较 |
| `decision` | 候选生成、可行性检查、支配关系筛选 |
| `report` | 可追溯的结构化报告 |
| `cmd` / `web` | 命令行样例与交互展示 |

核心模型与计算以 MoonBit 实现。界面复用同一计算核心，避免另外实现一套金融公式。依赖选择和版本在环境验证后确定。

## 5. 首版边界

- 支持固定、显式的还款计划；复杂浮动利率和不同机构的提前还款规则后续评估。
- 不把不明费用视作零，输入中保留缺失条款状态。
- 不自动连接银行账户，不承担支付操作。
- 自然语言输入、票据识别、更多账单格式作为增强项，不影响核心交付。
- 蒙特卡洛模拟只有在分布、数据来源和校准方法明确后才加入。

## 6. 验收大纲

- 三个完整使用场景可以从输入复现到报告。
- 金额与余额结果可用手工样例核对；利率求解可与公开参考实现交叉核验。
- 覆盖月底、闰年、同日收支、收入延迟、已有分期、后续付款和不可行方案。
- IRR / XIRR 对不支持的现金流明确报错，不输出看似可信的数值。
- 测试现金流守恒、压力情景变换和候选筛选规则。
- README、测试、CI、许可证、示例和 Mooncakes 发布满足赛事要求。
